# 硬盘、BIOS、UEFI 相关知识

这篇文章讨论的是“电脑如何找到硬盘、如何理解硬盘里的数据、又如何从硬盘启动系统”。如果把一台电脑想象成一座图书馆，硬盘就是书库，分区表是书库的平面图，文件系统是书架和目录规则，BIOS/UEFI 则是开门后负责找到第一本“启动说明书”的管理员。

![存储层次示意图](images/storage-stack.svg)

## 从一块硬盘说起

我们平时说的“硬盘”，通常指用于长期保存数据的块设备。它和内存最大的区别是：断电后数据仍然保留，但读写速度通常比内存慢得多。

常见硬盘可以按介质分成两类：

- **机械硬盘 HDD**：里面有高速旋转的盘片和磁头，容量大、价格低，但怕震动，随机读写慢。
- **固态硬盘 SSD**：使用闪存芯片保存数据，没有机械运动部件，随机读写快、抗震性好，但闪存单元有写入寿命限制。

也可以按连接方式和协议理解：

| 类型 | 常见外观或接口 | 传输协议 | 特点 |
| :-: | :- | :-: | :- |
| SATA HDD | 3.5 英寸/2.5 英寸硬盘 | SATA/AHCI | 容量大，速度受机械结构限制 |
| SATA SSD | 2.5 英寸硬盘或 M.2 SATA | SATA/AHCI | 比机械硬盘快，但被 SATA 带宽限制 |
| NVMe SSD | M.2 固态硬盘 | PCIe/NVMe | 延迟低、带宽高，是现在主流高速固态方案 |
| 移动硬盘/U 盘 | USB 接口 | USB Mass Storage/UASP 等 | 方便移动，性能和稳定性取决于设备本身 |

硬盘对操作系统呈现的不是“文件”，而是一串可以读写的地址空间。传统上这个最小地址单位叫 **扇区**，现代系统通常用 **LBA**（Logical Block Addressing，逻辑块寻址）来编号。文件、目录、权限这些概念并不是硬盘硬件天然知道的，而是文件系统在这些块上组织出来的。

## 分区表：告诉系统硬盘怎么切

一块硬盘可以被切成多个分区。比如 Windows 常见的 `C:`、`D:`，Linux 里的 `/dev/sda1`、`/dev/nvme0n1p2`，本质上都是同一块或不同硬盘上的分区。

分区表记录了每个分区从哪里开始、到哪里结束、是什么类型。没有分区表，操作系统就很难知道这块硬盘上哪些区域应该当作系统盘、数据盘或 EFI 启动分区。

![MBR 与 GPT 分区布局对比](images/mbr-gpt-layout.svg)

### MBR

MBR（Master Boot Record，主引导记录）是较早的分区表方案。它位于硬盘最开头的第一个扇区，里面同时放了两类东西：一小段启动代码，以及最多 4 个主分区的分区表记录。

MBR 的限制比较明显：

- 传统 MBR 通常只能很好地管理 2TB 以内的磁盘空间；
- 主分区最多 4 个，如果想要更多分区，需要使用扩展分区和逻辑分区；
- 分区表主要集中在硬盘开头，损坏后恢复成本较高；
- 它和传统 BIOS 启动方式关系很紧密。

MBR 不是完全不能用，但它更像老式纸质地图：简单、兼容旧设备，但表达能力有限。

### GPT

GPT（GUID Partition Table）是 UEFI 规范中的现代分区表方案。它把分区信息组织得更清晰，也更可靠。

GPT 的主要优点：

- 支持远大于 2TB 的磁盘；
- 支持更多分区，常见系统不再需要扩展分区这种绕法；
- 硬盘头部和尾部各保存一份分区表信息，便于校验和恢复；
- 每个分区都有全局唯一标识，系统识别更稳定；
- 通常与 UEFI 启动配合使用。

新电脑、新系统、新硬盘一般优先选择 GPT。只有在需要兼容老主板、老系统或特殊设备时，才考虑 MBR。

## 文件系统：告诉系统文件怎么放

分区只是划出一片区域，真正决定“文件怎么命名、目录怎么组织、权限怎么记录、空闲空间怎么管理”的，是文件系统。

![文件系统选择示意图](images/filesystem-choice.svg)

### FAT32、exFAT 和 NTFS

**NTFS** 是 Windows 上最常用的文件系统。它支持权限、日志、压缩、加密等功能，适合作为 Windows 系统盘和固定数据盘。缺点是跨平台写入支持不如 exFAT 简单，尤其在旧版 macOS 上默认不能直接写入 NTFS。

**exFAT** 可以理解为面向移动存储设备的现代 FAT 文件系统。它突破了 FAT32 单文件 4GB 的限制，并且在 Windows、macOS、Linux 上都有较好的支持，因此很适合 U 盘、移动硬盘、相机存储卡等需要跨平台读写的设备。

**FAT32** 的优势是兼容性极强，很多旧设备、主板固件、相机、打印机都认识它。但它有明显限制：单个文件不能超过 4GB，权限和日志能力也很弱。它适合小容量 U 盘、启动盘的兼容分区，或者需要兼容老设备的场景。

简单选择：

| 场景 | 推荐文件系统 | 原因 |
| :- | :-: | :- |
| Windows 系统盘或固定硬盘 | NTFS | 功能完整，权限和日志支持好 |
| Windows 与 macOS/Linux 之间交换大文件 | exFAT | 跨平台方便，支持大于 4GB 的文件 |
| 小 U 盘、旧设备、启动兼容分区 | FAT32 | 兼容性最好 |
| Linux 系统盘 | ext4 | 稳定成熟，发行版支持广泛 |

不建议简单地说“U 盘用 NTFS 会必然缩短寿命”。更准确的说法是：NTFS 的日志和元数据写入可能比 FAT32/exFAT 更频繁，在质量一般、容量较小的 U 盘上不一定划算；但真正影响寿命的主要因素仍然是闪存质量、写入量、主控和磨损均衡策略。

### ext4

ext4 是 Linux 上最常见的日志文件系统之一。它负责在磁盘或分区上组织文件与目录，类似 Windows 中 NTFS 的角色。

ext4 的特点：

- 成熟稳定，适合 Linux 系统盘、数据盘；
- 支持日志，突然断电后更容易恢复到一致状态；
- 工具链完善，修复、检查、扩容都比较常见；
- 不适合作为 Windows 与 macOS 之间的通用交换盘，因为其他系统默认支持不如 exFAT。

在 Linux 安装系统时，如果没有特殊需求，根分区 `/` 选择 ext4 是非常稳妥的方案。

## BIOS 与 UEFI：开机后谁先运行

按下电源键后，CPU 不会凭空知道操作系统在哪里。它会先运行主板固件。这个固件负责硬件初始化、自检、选择启动设备，并把控制权交给引导程序。传统固件叫 BIOS，现代固件通常叫 UEFI。

![BIOS 与 UEFI 启动流程](images/boot-flow.svg)

### BIOS

BIOS（Basic Input/Output System）是传统 PC 固件。它的启动模型很简单：自检硬件后，根据启动顺序找到某块硬盘，读取硬盘最开头的 MBR 扇区，把里面的一小段启动代码加载运行。

可以把 BIOS 启动理解成“管理员只看硬盘第一页”。这第一页空间很小，所以 MBR 里的代码通常不能直接完成复杂启动流程，只能再去加载后续的引导程序，例如 GRUB 的下一阶段代码。

典型流程：

1. 按下电源键；
2. BIOS 执行 POST 自检，初始化基本硬件；
3. BIOS 按启动顺序寻找可启动设备；
4. 读取目标硬盘的 MBR；
5. MBR 中的启动代码继续加载 bootloader；
6. bootloader 加载操作系统内核。

### UEFI

UEFI（Unified Extensible Firmware Interface）是现代固件接口。它不再只依赖硬盘第一个扇区里的短代码，而是能够识别 FAT 格式的 EFI 系统分区（ESP），并直接加载其中的 `.efi` 启动程序。

UEFI 启动更像“管理员能看懂目录并按记录找文件”。主板固件会读取 NVRAM 中的启动项，例如 `Windows Boot Manager`、`ubuntu`，然后到 EFI 系统分区里找到对应的启动文件。

典型流程：

1. 按下电源键；
2. UEFI 固件执行硬件初始化；
3. 固件读取 NVRAM 中保存的启动项；
4. 在 EFI 系统分区中找到 `.efi` 文件；
5. 加载 Windows Boot Manager、GRUB、systemd-boot 等引导程序；
6. 引导程序加载操作系统内核。

UEFI 常见特性包括图形化设置界面、Secure Boot、安全启动项管理、更好的 GPT 支持等。现在的新电脑基本都应优先使用 UEFI + GPT。

## BIOS + MBR 与 UEFI + GPT

实际装系统时，经常看到两组搭配：

| 搭配 | 常见设备 | 启动位置 | 特点 |
| :-: | :- | :- | :- |
| BIOS + MBR | 老电脑、老系统 | 硬盘第一个扇区 MBR | 兼容旧设备，但限制多 |
| UEFI + GPT | 新电脑、新系统 | EFI 系统分区中的 `.efi` 文件 | 结构清晰，支持大硬盘和更多分区 |

需要注意：BIOS/UEFI 是“主板固件启动方式”，MBR/GPT 是“硬盘分区表格式”，它们不是同一层概念。只是因为历史原因，BIOS 常和 MBR 搭配，UEFI 常和 GPT 搭配。

安装系统前要特别注意启动 U 盘的进入方式。同一个 U 盘在启动菜单中可能出现两项：

- `UEFI: USB Disk`
- `USB Disk`

如果想安装成 UEFI + GPT，应选择带 `UEFI:` 前缀的启动项。如果误用传统 BIOS 模式启动安装器，安装出来的系统可能会变成 BIOS + MBR，后续再切换就会比较麻烦。

## EFI 系统分区是什么

EFI 系统分区通常简称 ESP。它是 GPT 磁盘上一块较小的 FAT32 分区，常见大小是 100MB 到 1GB。这个分区里保存的是启动文件，不是普通用户数据。

常见路径示例：

```text
EFI/
├── Microsoft/
│   └── Boot/
│       └── bootmgfw.efi
├── ubuntu/
│   └── grubx64.efi
└── Boot/
    └── bootx64.efi
```

Windows、Ubuntu 等系统可以共用同一个 EFI 系统分区，但会放在不同目录下。多系统启动时，UEFI 固件或 GRUB 会根据启动项决定加载哪个 `.efi` 文件。

除非你明确知道自己在做什么，不要随意格式化或删除 EFI 系统分区。它通常不大，但它决定了系统能否启动。

## 常见安装建议

对于现在的大多数电脑，可以按下面原则选择：

- 新电脑安装 Windows 或 Linux：优先使用 **UEFI + GPT**；
- Linux 根分区：优先 ext4，除非你明确需要 Btrfs、XFS 等特性；
- Windows 系统盘：NTFS；
- 跨平台移动硬盘或 U 盘：优先 exFAT；
- 需要制作兼容性很强的启动盘小分区：FAT32；
- 2TB 以上硬盘：优先 GPT；
- 多系统共存：保留 EFI 系统分区，不要让安装器随意覆盖已有启动项。

## 排错时的思路

启动问题不要只盯着“系统坏了”，可以按层次从外到内检查：

1. **固件层**：BIOS/UEFI 是否识别到硬盘？启动顺序是否正确？Secure Boot 是否影响了第三方引导器？
2. **分区表层**：硬盘是 MBR 还是 GPT？安装器启动模式和目标分区表是否匹配？
3. **启动分区层**：EFI 系统分区是否存在？里面是否有正确的 `.efi` 文件？
4. **引导程序层**：Windows Boot Manager、GRUB 或其他 bootloader 是否还在？
5. **文件系统层**：系统分区是否损坏？是否需要文件系统检查？

把这些层次分清楚后，很多报错就不再是一团乱麻。例如“电脑找不到系统”可能是启动顺序错了，也可能是 EFI 分区损坏；“安装器不让安装到这块磁盘”可能是当前启动模式和分区表格式不匹配。

硬盘负责保存数据，分区表负责划地盘，文件系统负责管文件，BIOS/UEFI 负责在开机时找到引导程序。理解这四层关系，装系统、分区、修启动都会清晰很多。
